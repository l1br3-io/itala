# wasmtime + Component Model

Single-page reference for hosting WASM plugins.

## Why component model

The component model gives:
- **Strongly-typed host/guest boundary** via WIT (no manual ABI plumbing).
- **Resources** (handles owned by the host, referenced by the guest) with deterministic lifetimes.
- **Async** support across the boundary in wasmtime ≥ 25.
- **Composition**: components can import each other, not just the host.

For Itala, the component model is the right plugin runtime. Don't fall back to core WASM unless a specific plugin can't be expressed as a component.

## Engine setup

```rust
use wasmtime::{Engine, Config};

let mut config = Config::new();
config.wasm_component_model(true);
config.async_support(true);
config.consume_fuel(true);              // for cancellation budgets
config.epoch_interruption(true);        // for time-based cancellation
let engine = Engine::new(&config)?;
```

One engine per process. Cheap to clone (`Arc` internally).

## Linker (host imports)

```rust
use wasmtime::component::Linker;

let mut linker: Linker<HostState> = Linker::new(&engine);
host_vfs::add_to_linker(&mut linker, |state: &mut HostState| &mut state.vfs)?;
host_events::add_to_linker(&mut linker, |state: &mut HostState| &mut state.events)?;
```

`host_vfs::add_to_linker` is generated by `wit-bindgen` from the WIT. The closure projects from the per-store host state to the trait impl.

## Store + instantiation

```rust
use wasmtime::Store;

let mut store = Store::new(&engine, host_state);
store.set_fuel(10_000_000)?;            // budget per call
store.set_epoch_deadline(1);            // wall-clock cancellation

let component = Component::from_file(&engine, "plugin.wasm")?;
let (plugin, _) = Plugin::instantiate_async(&mut store, &component, &linker).await?;
```

One store per plugin instance. Stores carry per-instance state (capabilities granted, plugin-local data).

## Calling guest exports

```rust
let html = plugin
    .editor()
    .call_render_block(&mut store, &ctx, &ast_bytes)
    .await?
    .map_err(Error::PluginRenderFailed)?;
```

Generated bindings produce typed methods — no manual `Func::typed` plumbing.

## Resources

WIT `resource` types translate to `wasmtime::component::Resource<T>`:

```wit
interface host-vfs {
    resource note-handle {
        read: func() -> result<list<u8>, string>;
    }
}
```

```rust
impl host_vfs::HostNoteHandle for HostState {
    async fn read(&mut self, h: Resource<NoteHandle>) -> Result<Vec<u8>, String> {
        let note = self.handles.get(h.rep())?;
        // …
    }
}
```

The host owns the underlying data; the guest holds an opaque handle. Drop the resource on the guest side → wasmtime deallocates host-side.

## Cancellation

Two mechanisms:
- **Fuel**: `store.set_fuel(N)`; instructions consume fuel; trap on exhaustion. Use for compute caps.
- **Epoch**: `engine.increment_epoch()` from a timer; trap when deadline reached. Use for wall-clock caps.

Pick fuel for "this plugin call shouldn't take more than 100M instructions" and epoch for "kill if it runs over 5s of wall time."

## Trapping

Plugin panics are wasmtime traps. Catch via `Result::Err(wasmtime::Error)`:

```rust
match plugin.editor().call_render_block(&mut store, ...).await {
    Ok(Ok(html)) => html,
    Ok(Err(msg)) => /* plugin returned WIT error */,
    Err(trap) => /* plugin panicked, fuel exhausted, etc. */,
}
```

Mark the plugin as crashed; surface to the user; don't propagate the trap into the host.

## Capability gating

Before instantiation, build a `Linker` that only links the capabilities the plugin's manifest declared. Implement this as a function that takes the manifest and returns a configured linker:

```rust
fn linker_for(manifest: &Manifest, engine: &Engine) -> Result<Linker<HostState>> {
    let mut linker = Linker::new(engine);
    for cap in &manifest.capabilities.required {
        match cap.as_str() {
            "host.vfs.read"   => host_vfs::add_read_to_linker(&mut linker, …)?,
            "host.vfs.write"  => host_vfs::add_write_to_linker(&mut linker, …)?,
            "host.events"     => host_events::add_to_linker(&mut linker, …)?,
            other => bail!("unknown capability: {other}"),
        }
    }
    Ok(linker)
}
```

Optional capabilities are added when (and if) the user grants them.

## Versioning

`Component::from_file` succeeds if the component's WIT world matches what the host links. Validate the WIT package version on the manifest before instantiation; refuse mismatched majors.
