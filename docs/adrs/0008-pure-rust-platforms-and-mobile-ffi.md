# ADR-0008 — Pure Rust everywhere; native mobile shells consume the core via UniFFI

- **Status:** Accepted
- **Date:** 2026-11-01
- **See also:** [ADR-0005](./0005-plugin-trust-and-rollout.md), [research](../research/2026-11-01-pure-rust-feasibility.md)

## Context

The platform matrix (ARCHITECTURE §9) sketched a Tauri desktop shell with a
TypeScript webview frontend, and Rust UIs were long considered too immature
to bet on. Two things changed the calculus:

1. **The native Rust UI story matured.** iced shipped IME support (0.14,
   Dec 2025) and carries a desktop-scale existence proof (System76's
   COSMIC); GPUI — the framework behind Zed, the strongest existence proof
   that a latency-leading editor can be pure Rust — was published on
   crates.io under Apache-2.0 (Oct 2025). Web-first Rust frameworks
   (Leptos/Yew/Dioxus) are judged production-ready as of early 2026. The
   feasibility research ([link](../research/2026-11-01-pure-rust-feasibility.md))
   verified these claims against primary sources and found no blocker; the
   residual risk concentrates in desktop editor polish and accessibility
   parity, both shrinking and both isolated to the shell by the hexagonal
   architecture.
2. **The mobile pattern is proven in-repo.** taletrek (l1br3) ships native
   iOS/Android apps over an agnostic Rust core through a thin UniFFI surface
   crate: every decision stays in Rust; the wrappers only flatten types and
   forward calls. Bindings are generated and checked in, regenerated by
   `just` recipes, and native build systems never invoke Cargo.

VISION ranks learning and craftsmanship as success criterion #1 with no
deadline, which favors one language across product surfaces — provided the
product goals remain achievable, which the research supports.

## Decision

1. **Product surfaces are authored in Pure Rust except mobile.** Desktop and
   web shells contain no TypeScript codebase. The kernel, contexts, and
   adapters stay free of UI dependencies (already true today).
2. **Mobile shells are fully native** (SwiftUI / Jetpack Compose) and
   consume the Rust core through a thin UniFFI surface crate (`itala-ffi`,
   target): no logic, no decisions — only type flattening and forwarding.
   Bindings are checked in and regenerated by `just` recipes; Gradle and
   Xcode never invoke Cargo.
3. **The desktop renderer is deliberately not chosen yet.** It is decided at
   MVP-β kickoff via editor prototype spikes between **iced** and **GPUI**.
   A Rust-authored webview shell (Tauri + Leptos, or Dioxus desktop) is the
   recorded fallback if both spikes disappoint — not the default.
4. **Third-party plugin hosting (M5) treats the runtime as a port.** The
   plugin ABI is defined in WIT so one plugin package runs on any conformant
   host; adapters are per-platform (wasmtime natively; jco-transpiled or
   wasmi on the web; wasmi if mobile ever hosts plugins). Mobile shells do
   not host third-party plugins at launch.
5. **Cross-shell representations stay renderer-agnostic.** The M2 document
   engine's render target is a semantic render tree (pure IR, no HTML,
   widget, or terminal assumptions); concrete renderers live shell-side
   (terminal renderer in the CLI, native attributed-string renderers on
   mobile, the chosen UI toolkit at MVP-β).

## Consequences

- **Positive:** one language across product surfaces maximizes the learning
  goal; mobile users get genuinely native editors (IME, accessibility, text
  controls for free); core portability becomes continuously provable with a
  `wasm32` compile check in CI.
- **Positive:** deferring the iced-vs-GPUI choice costs nothing — the shell
  is isolated — so M2 proceeds with only the render-IR shape decided.
- **Negative:** desktop editor polish is the accepted risk: native Rust rich
  text is younger than web tech. Mitigations: MVP-β spikes decide on
  evidence, the webview fallback is recorded, and the render IR keeps the
  engine renderer-neutral so the fallback is cheap.
- **Negative:** `itala-ffi` is a maintained public surface — UniFFI version
  pinning, generated-bindings churn in reviews, and change discipline (the
  taletrek GOTCHAs document several traps).
- **Neutral:** egui is ruled out for the editor surface (large-text layout
  performance) and Slint on licensing (GPL/commercial); the iOS no-JIT
  constraint stays dormant because mobile does not host plugins at launch.
- **Follow-ups:** add a `wasm32-unknown-unknown` compile check for core
  crates (candidate M2 success criterion); an MVP-β spike comparison note;
  a dedicated ADR for the concrete plugin runtime choices at M5; update
  ARCHITECTURE §1/§2/§4.3/§9 accordingly.
